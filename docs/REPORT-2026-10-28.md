What r4 got right that r3 did not: the Macedo checklist and the Alcácer file-naming list are no longer called elements
(the new noise kinds worked). What r4 still gets wrong, all the same failure:

- the four real memórias (Valongo loteamento, three Cascais loteamentos) are called "not an element";
- the OA minuta of the author's termo is called "not an element" (r3 had it right).

Diagnosis (read the prompts, not the scores): the reader sees the first 3,500 characters of each file. For a 30-page real
memória that is a cover page plus a long dotted table of contents, which looks exactly like the checklist and file-list
noise it was just taught to reject. The Valongo memória opens as a letter ("Resposta ao ofício n.º …"). The OA minuta
extracts as one word per line and opens with "A presente minuta … transcreve a redação prevista …". None of those shapes
existed in the training expedientes.

Key fix: the Valongo area key said "49 977,00 m2"; every value in the data set is written without its unit (the unit is in
the question), so the key was out of convention. Fixed in generator/stranger.py and sealed/stranger-test.jsonl (one
line). Rescored on the fixed key: r3 5/7, r4 7/7 on D2 value. No training data touched.

## Round 5 (done 06:49 UTC): the cover-and-index theory was wrong

Training-data changes only (sealed sets untouched, commit 253e3c4):

1. long memórias (now 50 % of expedientes) come in two real shapes: cover page → page of dotted index with sub-numbering
   (3.4.1.1 …) and a running atelier/department header → body; or the ofício-reply header (company, "Resposta ao ofício
   n.º …/DGU.SAA", site, title + month, atelier footer, "1. NOTA EXPLICATIVA");
2. four title spellings (Memória Descritiva, MEMÓRIA DESCRITIVA E JUSTIFICATIVA, …);
3. 15 % of author and coordinator termos open with the minuta preamble line;
4. augmentation (45 % of files, training only): OCR noise, or one word per line, or both.

Result: lab tests held (sealed D1 100 %, D2 100 %, D0 transcreve 100 %, localiza 96 %, exigencia 93 %); stranger still 6/11.
The OA minuta flipped to correct (+1), the Alcácer file-naming list flipped to wrong (−1), the four real memórias still "not an element".
D2 stranger 7/7. Cost: 14,2k examples, 1,017 steps, 3.47 h H100 (≈ USD 14).

## The probe that found the real cause (no training, two reader runs, ≈ USD 1)

1. Municipality swap: the real memórias rewritten with "Celorico de Basto" and "comunicação prévia" → still wrong; generated
   memórias rewritten to "Cascais" and "loteamento" → still right. Not the municipality.
2. Ten ablations on three real memórias (Cascais 1145, Cascais 1037, Valongo):

| change to the real file | result |
|---|---|
| nothing | wrong (3/3) |
| **file name → MDARQ-memoria-descritiva.pdf** | **right (3/3)** |
| page count → 4 | wrong |
| index page removed | wrong |
| whitespace normalised | wrong |
| body only (from page 3) | wrong |
| **generated memória text under the real file name** | **right (3/3)** |
| the generator's intro sentence pasted into the real text | right 2/3 |

**The reader decides by the file name.** Every training file is named by its slot code (MDARQ-memoria-descritiva.pdf,
TRPARQ-termo-arquitetura.pdf, OUTDOC-…), and every "stranger name" augmentation style still carried the slot or the stem.
Real files arrive as cascais_md_loteamento_1145.pdf, valongo_74l2023_md.pdf, scan.pdf. Unknown name → "not an element".
